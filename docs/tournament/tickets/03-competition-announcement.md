# 03：賽前公告完整競賽方案

**Priority:** P1

**What to build:** 主辦能在賽前保存並公告首輪時間、各階段賽制與時計、晉級來源、種子政策及完整排序政策；先比自身積分高，同分才比勝分多、負分少，不再比較血量或耗時。全項相同由主辦／無利益衝突裁判限定判斷並公開理由，不提供排名同分加賽格式。瑞士階段另完整公告引擎建立與配對所需的 `SwissStandingPolicy`，包括四項積分、和局折算、對手勝率上下限、輪空取值及同分鍵；非瑞士階段不可帶入瑞士設定。參賽者可查看同一公告版本，截止後不必補填賽程設定。不重做已通過的設定元件。

**Blocked by:** 無（無功能票前置；仍須依索引協調唯一寫入權）。

**Status:** ready-for-agent

**類型：** 新增／重用既有設定

**政策引用：** 公告引用[設計的排序與瑞士配對定義](../competitive-play-design.md#晉級與前三名的排序判定)，也要逐項列出瑞士政策，不能藏預設；政策確認不代表公告功能已實作或驗證。

## 驗收條件

- [x] 主辦賽前保存同一版本的規則、個人／團體、各階段賽制、交手格式、時計、首輪 T 與資格／種子來源；參賽者可查閱。
- [x] 報名截止與 T 精確到分鐘；主時間 0 表示不限時，讀秒只提供既定三種選項，生命依規則衍生。
- [x] 公告引用設計中的排序、瑞士配對與限定主辦處置；不提供血量／耗時比較或排名同分加賽格式。
- [x] 後續自動化能直接使用公告版本，不在截止後要求主辦補填或確認；保存／讀取元件案例通過。

共用驗收與工作規則見[票據索引](README.md#共用驗收與工作規則)；產品政策見[競賽設計](../competitive-play-design.md)，現況與放行證據見[審核關卡](../competition-review-gates.md)。
