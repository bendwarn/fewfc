# 測試賽事控制

此功能只在 `APP_ENV=development` 使用。主辦在建立賽事頁勾選「建立僅供開發環境驗證的測試賽事」，可為兩隊指定相同的初始生命值。賽事 ID 以 `test-` 開頭，賽事頁會標示測試用途；正式賽事仍依規則決定生命值。staging 與 production 的測試建立入口回傳 404。

測試賽事的主辦可在賽事頁輸入賽程上的交手 ID，暫停或恢復已開局的時計。操作會先讀取交手版本，經賽事房驗證主辦身分與目前遊戲房狀態，再使用既有時計命令和跨房交付。玩家無權操作。若時計在暫停前已耗盡，控制會遭拒，既有超時處理仍會繼續。若回應結果不明，頁面保留相同命令供重試；離開或重新整理頁面不會撤銷已送出的命令。

共用牌庫的測試賽事可在玩家準備開局前設定起手牌：每行依回合順序填一名玩家的牌，先手四張、其餘各五張；例如 `火 4, 火 4, 金 1, 木 1`。每張牌必須存在於該賽事的正式牌庫，重複數量不能超過實際副本。個人牌組與錦囊目前不支援此功能。規則引擎以指定順序正常發牌並記錄完整牌序；主辦不能改寫開局後的手牌，玩家仍只能看到自己的牌。

例如設定雙方初始生命為 4，先手使用兩張火牌蓋反震，後手使用金 3 施展金擊術，可由真實規則處理雙方傷害並產生和局。仍須以實際終局和重播確認結果。此功能不直接指定勝負或改寫剩餘時間；測試賽事的自訂生命、起手牌與主辦時計操作只能作為測試情境證據，不能代表正式規則或未介入的流程已驗收。
