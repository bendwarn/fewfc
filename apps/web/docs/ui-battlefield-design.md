# 對局介面改版設計

更新日期：2026-10-22。設計方向已在訪談中確認，供後續實作與驗收使用；本文件不表示介面已完成改版。

核心原則：平時顯示摘要，依當前情境展開細節。隊伍 HP、手牌與必要回應提示保持可辨識，完整細節由可主動開啟的詳情介面承接。

## 已確認方向

### 範圍與視覺依據

- 首波聚焦對局畫面，涵蓋玩家、旁觀與重播視角；大廳、帳號及賽事管理頁留待後續。
- 保留現有手機操作骨架，再套用新版視覺。桌機使用紀錄側欄，手機使用可展開的紀錄面板，優先保留手牌與當前操作空間。
- 示意圖提供美術方向；尺寸、資訊密度及互動以訪談確認後的文字規格為準，不要求逐像素重現。
- 中央情境行動面板承接現有能力與行動選擇；複雜的選牌、選玩家等待選流程保留專用介面，專用介面也套用新版視覺。
- 未選牌時仍須呈現不需選牌的合法操作。「誰的回合」與「現在由誰選擇」分開呈現，以涵蓋回合外選擇。

### 能力與行動的辨識

同一個情境行動面板保留兩個分組，分組名稱與固定提示放在各框右側，不設頂部 header；以名稱、固定提示及按鈕層級共同區分：

| 分組 | 固定提示 | 內容例子 | 按鈕層級 |
|---|---|---|---|
| 能力 | 使用後仍可行動 | 職業能力、精靈技能、秘計、棄牌回收 | 較輕的描邊按鈕 |
| 行動 | 本回合擇一 | 施展陣法、轉職 | 較明顯的實底按鈕 |

- 可收合長篇說明；面板顯示時，兩個分組名稱與固定提示始終可見，玩家不必展開詳情才能辨識操作類型。
- 選中行動後，在詳情旁保留「本回合行動」標記；僅選中或填寫輸入不代表已提交。
- 能力完成後更新可用選項，保留操作面板；是否仍有可用能力或行動由引擎提供的合法選項決定。
- 行動被伺服器接受後，依權威狀態切換至後續結算、待選或抽牌流程。
- 不將行動描述為「使用後結束回合」，因為後續可能仍有必要選擇與回合抽牌。

### 對局導覽與回合提示

- 桌機對局 header 平時隱藏，游標接近頂端或鍵盤焦點進入時顯示；採浮層呈現，不佔位、不改變戰場幾何。手機維持可見導覽。
- 回合提示保持單行，過長文字省略並可查看完整提示；輪到視角玩家時循環發光，尊重減少動態效果設定。

### 環境背景與外觀

- 背景依對局的環境自動切換，同時保留玩家的系統／亮色／深色外觀偏好；環境與明暗是不同的控制來源。
- 「無」背景代表無環境，適用於開局、環境被破除及未啟用相關規則的對局。它不是第六種規則元素或環境。

### 依情境展開玩家資訊

- 接受畫面無法同時呈現所有細節，以當前情境決定展開哪些資訊；其他資訊先提供摘要。
- 四人對局保留視角玩家在底部，其餘三名玩家（包含隊友）的資訊欄共用上方一列；桌機與手機都採用此配置。
- 三人排列順序固定，只調整欄位寬度，不因輪到誰而交換位置。
- 伸縮以橫向為主，限制整列高度，避免展開時把戰場與手牌往下擠。放不下的完整細節由桌機浮層或手機底部詳情面板承接。
- 四人對局上方三席只在該玩家的回合展開；必要回應保留醒目提示與詳情入口，不改變展開對象。「回合玩家」與「目前決策者」分別標記。
- 玩家可隨時手動打開其他玩家的詳情；閱讀中的內容不因回合切換而自動關閉。新的回應要求另外醒目提醒。
- 收合欄位至少保留姓名／隊伍、職業、手牌張數及重要狀態標記。精靈、靈力、錦囊與效果說明放在展開內容；會影響當前選擇的狀態仍在相關操作旁提示。
- 兩人對局的玩家區總是展開。桌機對手區與左側陣法區同寬，右側能力與行動區跨越對手、陣法兩列；自己的手牌區維持底部全寬。手機維持上下兩區全寬，視角玩家自己的手牌始終可見。
- 展開的上方玩家區以小牌背逐張表示手牌數，不再重複顯示張數文字；牌背與自己的手牌採相同靠左起點，接在玩家資訊之後，詳情入口置右。固定牌背高度，長手牌在區內橫向捲動，不推高玩家區。
- 此處的「玩家資訊欄」是介面呈現，不改變 Player Seat 的身分綁定、Team、Turn Order 或可見資訊權限。

### 旁觀與重播定位

- 旁觀時以先手玩家固定在底部，其餘玩家依固定順序排列；不隨回合自動旋轉座位。
- 重播時以選定視角的玩家固定在底部。切換重播視角才改變定位，播放或步進只改變當前狀態與展開欄位。
- 座位定位與資訊可見性分開處理；仍依既有旁觀、一般重播及公開賽事重播的資料過濾規則呈現。

### 閱讀詳情與必要回應

- 正在閱讀詳情時收到屬於觀看玩家的必要回應要求，在詳情面板內顯示持續可見的「需要你回應」入口。
- 保留正在閱讀的內容與鍵盤焦點，由玩家點擊入口後切換至專用待選介面；不因新待選項直接搶走閱讀焦點。
- 這取代目前必要待選視窗一到達就自動開啟並移動焦點的行為。保留的是閱讀狀態，待選要求本身仍由權威遊戲狀態決定。

### HP 呈現與資料來源

- 兩人與四人對局皆維持兩隊 HP 的固定顯示位置，不隨玩家資訊欄收合。
- 每隊只顯示目前值／上限數字及 HP 長條，以顏色識別隊伍，不增加可見的隊伍文字標籤。
- HP 仍屬於 Team，個人資訊欄不重複呈現共用 HP。
- HP 上限可以從對局紀錄取得或推導，不以缺少公開狀態欄位為理由直接要求新增上限欄位。
- 實作時需涵蓋首次載入、重連與重播，確保同一局取得一致的初始 HP；不能把中途快照的目前 HP 當成上限。

已查明的資料現況：伺服器保存的 Game Record 含開局設定與完整規則紀錄，引擎也保留 initial HP；目前瀏覽器的 Public Game State 只有目前 HP，Battle Record 只有顯示用文字。重連與重播皆經公開投影回傳。因此「從紀錄推導」的實作應利用開局設定或初始狀態產生所需的公開資料，避免依賴中文敘述句型；不需讓瀏覽器取得完整 Game Record。

## 與既有文件的關係

- [UI Platform Decision](./platform-decision.md) 的規則引擎權威、Public View 與隱藏資訊邊界持續適用。
- [ADR-0028](../../../docs/adr/0028-treat-action-detail-as-contextual-supplement.md) 已允許依決策情境組織說明，但要求玩家能在提交前辨識已選輸入、額外代價及重要結果。資訊收合不能省略會改變當前決策的事實。
- [規則引擎決策第 37 節](../../../docs/rules-engine-decisions.md) 持續要求能力與行動在語意上可區分，以及各玩家的職業標示；具體版面採本文件的情境面板、摘要與展開方式。
- 沒有找到要求所有公開資訊同時顯示的既有決策；目前窄版已有摘要與詳情面板。新版已確認桌機與手機四人對局皆採上方三人同列，取代目前桌機上下左右座位的版面標準；實作時需同步更新相應驗收。

## 後續實作的驗收重點

- 兩人／四人、桌機／手機，以及玩家／旁觀／重播皆遵循各自已確認的定位與欄位規則。
- 四人上方三欄在回合與決策者切換時位置不交換，摘要可操作，手牌與戰場不被伸縮擠出可用視窗。
- 回合外選擇能正確標示回合玩家與決策者，上方玩家區仍依回合玩家展開。
- 手動開啟的詳情可跨回合持續閱讀；新必要回應的入口可用鍵盤操作，點擊後才切換並移動焦點。
- 兩隊 HP 各顯示一組數字與長條，以隊伍色識別；初始上限在首次載入、重連與重播間一致。
- 未選牌時仍有合法的零選牌操作，能力與行動的語意差異可辨識；專用待選介面採新版視覺。
- 能力與行動在同一面板分組，分別顯示「使用後仍可行動」及「本回合擇一」；收合長篇說明後，分組名稱與提示仍可見。
- 能力採描邊按鈕，行動採實底按鈕；選中行動時顯示「本回合行動」，完成能力與接受行動後各自呈現正確的後續流程。
- 環境背景與明暗外觀可獨立變化，無環境時使用「無」背景。
- 在 Storybook 建立對局整頁或多元件組合的 stories，涵蓋上述人數、裝置、視角、環境與明暗狀態；外觀及版面只在 Storybook 透過人工檢視或對已確認基準的截圖比對驗收。
- 以 Storybook 互動測試或對 stories 執行的 Playwright DOM、可存取名稱、焦點與幾何斷言驗證互動；同步更新既有桌機四方位等已被新設計取代的版面斷言。
- 以少量代表性 E2E 流程驗證實際指令提交、Rust 處理後的 UI 更新、多人同步、重連、重播資料與隱藏資訊邊界；詳細分工依 [Storybook 指南](./storybook.md#validation-scope)。

具體色值、欄寬、列高與動畫參數屬後續實作調整，須符合上述行為與可讀性要求。原始 UI kit 內的工具清單與 CSS 範例是參考資料；實作沿用既有 Nuxt 堆疊，依實際需求選用工具。示意圖的卡牌名稱、費用與效果不作為遊戲規則依據。
